# Handoff F4-06: Aplikacja wysyła status nagrań z zegarka do modułu

Plik przekazania pracy między sesjami i agentami (Claude ↔ Gemini). Aktualizuj go na koniec
każdej sesji (workflow /os-handoff). Następny agent zaczyna od przeczytania tego pliku.

**To ostatnie zadanie MVP Fazy 4 (Apple Watch) — po scaleniu cała faza jest odhaczona poza
świadomie nieplanowanym punktem "Po MVP".**

## Stan
- `domain/services/IWatchConnectivity.ts`: dodano `sendRecordingStatus(id, status): Promise<void>`
  do interfejsu (sygnatura zarezerwowana pojęciowo w F4-03/F4-05, tu trafia do domenowego
  kontraktu).
- `infrastructure/watch/expoWatchConnectivity.ts`: `ExpoWatchConnectivity.sendRecordingStatus`
  woła już istniejące API JS z `modules/watch-connectivity` (zaimplementowane natywnie w F4-05).
- `application/store/useNotesStore.ts`: `setNotesDependencies` przyjmuje teraz opcjonalny
  `watchConnectivity`; `updateRecordingRealtime` (już nasłuchujące Supabase Realtime od F2-07)
  woła `activeWatchConnectivity.sendRecordingStatus(recording.id, recording.status)` wyłącznie
  gdy `recording.source === 'watch'`, w `.catch(() => {})` — błąd wysyłki statusu na zegarek nie
  może zepsuć aktualizacji stanu aplikacji.
- `composition/diary.ts`: drugie wywołanie `setNotesDependencies({ watchConnectivity })` po
  utworzeniu instancji `watchConnectivity` (z F4-04) — `setNotesDependencies` scala tylko podane
  klucze, więc nie nadpisuje `recordingRepository`/`noteRepository` ustawionych wcześniej w pliku.
- Testy: 2 nowe w `useNotesStore.test.ts` (status wysyłany dla `source: 'watch'`, NIE wysyłany dla
  `'phone'`/`'web'`). Pełny `npx jest --ci`: 84/84. `npx tsc --noEmit`/`npx eslint` czyste.
