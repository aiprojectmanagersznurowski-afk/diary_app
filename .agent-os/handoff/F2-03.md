# Handoff F2-03: Warstwa _shared/ai z adapterami Groq i Gemini

Plik przekazania pracy między sesjami i agentami (Claude ↔ Gemini). Aktualizuj go na koniec
każdej sesji (workflow /os-handoff). Następny agent zaczyna od przeczytania tego pliku.

## Stan
Zaimplementowano warstwę `supabase/functions/_shared/ai` oraz konfigurację `supabase/functions/_shared/config`:
- Interfejsy `SttProvider`, `LlmProvider` (w tym JSON i streaming SSE), `EmbeddingProvider` w `types.ts`.
- Mechanizm ponawiania `fetchWithRetry` w `retry.ts` (kody 429 i 5xx, wykładniczy backoff, obsługa nagłówka `Retry-After`).
- Adaptery Groq (`GroqSttAdapter` dla Whisper, `GroqLlmAdapter` dla Llama z obsługą formatu JSON i SSE stream).
- Adaptery Gemini (`GeminiLlmAdapter` z obsługą systemInstruction, JSON i SSE, oraz `GeminiEmbeddingAdapter` z weryfikacją `dimension === EMBED_DIM`).
- Fabrykę `createAiProviders` oraz per-task factory z dynamiczną konfiguracją przez zmienne środowiskowe.
- 16 testów jednostkowych Deno (`deno test --allow-all supabase/functions`) przechodzi w 100%.

## Następny krok
Recenzja krzyżowa i scalenie do `main`, następnie przejście do zadania F2-04 (Edge Function `process-recording`).

## Kryteria akceptacji
- [x] zmiana dostawcy/modelu zadania wymaga tylko zmiany zmiennej środowiskowej
- [x] embeddingi mają długość EMBED_DIM (1536); inna długość = błąd
- [x] deno test: każdy adapter z atrapą fetch (sukces, 429 z ponowieniem, błąd), bez prawdziwych kluczy
- [x] żaden plik poza _shared/ai nie woła dostawców (bramka ai-boundary)

## Decyzje w trakcie
- Czysty `fetch` bez zewnętrznych SDK (zgodnie z wytycznymi bramki `ai-boundary` i ograniczeniami CP-DEP).
- Ponawianie `fetchWithRetry` dla kodów 429 (Rate Limit) i 5xx (500, 502, 503, 504) z obsługą nagłówka `Retry-After`.
- Domyślny wymiar embeddingu: 1536 (maksymalny dla indeksu HNSW w pgvector).
