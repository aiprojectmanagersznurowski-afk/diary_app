### Rozwiązanie problemu `dod:db-test`
Po scaleniu PR #7 (poszerzenie logu o błędy do 200 linii) i rebase, pełny log z `supabase test db` ujawnił dokładną przyczynę:
`pgTAP` przy 2- i 3-argumentowym wywołaniu `throws_ok(sql, errcode, errmsg)` traktował trzeci argument jako **oczekiwany error message**, a nie opis testu (wcześniej opis testu po polsku był porównywany z komunikatem błędu PostgreSQL).
Poprawka: użycie pełnej formy 4-argumentowej `throws_ok(sql, errcode, errmsg, description)` z dokładnym komunikatem rzucanym przez PostgreSQL przy naruszeniu reguły RLS: `'new row violates row-level security policy for table "objects"'`.
Po tej zmianie testy storage w `021_storage.test.sql` przeszły 6/6.
