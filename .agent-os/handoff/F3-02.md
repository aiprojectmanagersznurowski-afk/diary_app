## Decyzje w trakcie
- `upsertDailyDocument` robi upsert po `id`, nie po `(user_id, slug)` — dokumenty mają unikalny
  indeks częściowy `documents_one_daily_per_day (user_id, day) where kind='daily'`, który PostgREST
  nie potrafi użyć jako celu ON CONFLICT bez dopasowanego WHERE. Upsert po PK `id` omija ten problem
  i dodatkowo gwarantuje brak dryfu ID między przebudowami (ważne dla FK z document_chunks/links).
- Prompt digestu ładowany z `_shared/prompts/digest.v1.md` (już istniał, ale szkic ze stasha miał
  identyczną treść zahardkodowaną w kodzie) — zgodne z twardą regułą AGENTS.md o wersjonowanych
  plikach promptów. Uwaga: `process-recording/pipeline` (faza 2, już scalone) łamie tę samą regułę
  (DEFAULT_STRUCTURE_PROMPT/DEFAULT_LINK_PROMPT zahardkodowane mimo istniejących structure.v1.md/
  link.v1.md) — poza zakresem tego zadania, nie ruszałem.
- Adapter Supabase dla build-daily leży w `supabase/functions/build-daily/dbClient.ts`, nie w
  współdzielonym `_shared/db/supabaseClient.ts` — decyzja wymuszona przez scope.write kontraktu
  (patrz wyżej), nie tylko preferencja stylistyczna.
