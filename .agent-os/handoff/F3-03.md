# Handoff F3-03: Ekran szczegółów dnia na nowym modelu dokumentów

Plik przekazania pracy między sesjami i agentami (Claude ↔ Gemini). Aktualizuj go na koniec
każdej sesji (workflow /os-handoff). Następny agent zaczyna od przeczytania tego pliku.

## Stan
Nowe pliki domain/application/infrastructure + przepisany DetailScreen.tsx:
- `domain/models/DailyDocument.ts`: model wpisu dnia (pola DigestOutput przeniesione do TS bez zod,
  bo supabase/functions/** to osobny runtime Deno, nie da się dzielić typów z zod).
- `domain/repositories/IDocumentRepository.ts`: `getDocumentById(id)` zwraca `DailyDocument |
  NoteDocument | null`, rozróżnienie po `kind`.
- `infrastructure/supabase/supabaseDocumentRepository.ts`: `SupabaseDocumentRepository` + eksportowana
  czysta funkcja `mapRowToDailyDocument` (przetestowana); dla kind='note' woła istniejący
  `mapRowToNoteDocument` z F2-07 zamiast duplikować mapowanie.
- `application/useCases/documents/getDocumentUseCase.ts`: cienki use case, wzorowany na
  `GetNotesUseCase`.
- `composition/diary.ts`: dopisano `documentRepository`/`getDocumentUseCase` (patrz "Decyzje w
  trakcie" — to była zmiana poza pierwotnym scope.write, zatwierdzona przez CP-TASK).
- `DetailScreen.tsx`: przepisany od zera pod nowy model. Pobiera dokument przez
  `getDocumentUseCase.execute(route.params.entryId)` (zamiast `useDiaryStore`), renderuje pełny
  dashboard dla kind='daily' (te same sekcje co dawniej, ale z prawdziwych, już zwalidowanych pól
  zamiast stosu fallbacków na stare/niepewne kształty danych) i osobny, prostszy widok dla
  kind='note'. Sekcja pomysłów (`ideas`) linkuje do notatek przez `navigation.push('Detail', {
  entryId: idea.documentId })` — ten sam route, bo `entryId` teraz znaczy uniwersalnie
  "documents.id", nie tylko id starego wpisu dnia. Dodano zakładkę "Podgląd pliku .md" (rozwijana,
  jak dawna zakładka transkrypcji) pokazującą `daily.bodyMd`.
- Testy: 71/71 `npx jest --ci` (4 nowe: `getDocumentUseCase.test.ts`,
  `supabaseDocumentRepository.test.ts` — w tym `composition.test.tsx`, który nadal przechodzi mimo
  zmiany w `composition/diary.ts`). `npx eslint` i `npx tsc --noEmit` czyste.
